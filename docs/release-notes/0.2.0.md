# Blue Pine Solutions Mail 0.2.0

Version 0.2.0 adds mail-client access to the Node/Docker build. Blue Pine Solutions Mail is not presented as production-ready; see the limitations below.

## What's new

- **Mail app passwords.** Per-mailbox credentials for mail clients, scoped to IMAP and/or SMTP submission, shown once at creation and stored only as a hash. Create them under Settings → App passwords. The account's web password is never accepted by the mail listeners.
- **IMAP** (off unless `IMAP_PORT` is set; implicit TLS, port 993). Mailbox discovery, selecting and fetching mail, search, read and starred flags, MOVE, COPY, creating, renaming and deleting custom folders, stored subscriptions, recoverable and permanent deletion, saving drafts (APPEND, Drafts only), and live updates (IDLE).
- **Authenticated SMTP submission** (off unless `SMTP_SUBMISSION_PORT` is set; implicit TLS, port 465), using SMTP-scoped app passwords with the full mailbox address as the username. Clients can only send as the authenticated mailbox.
- **Server-owned Sent.** The server stores the Sent copy of every accepted submission. Mail clients must not upload their own: in Thunderbird, disable "Place a copy in" for the account.
- **Canonical message storage and a typed send path**, which the IMAP server, the original-message download and SMTP submission share. Delivery results now distinguish rejection, temporary failure and unknown outcome.
- **Thunderbird certification.** IMAP and SMTP submission were tested with Mozilla Thunderbird 157.0 on Windows against a local Docker runtime.
- **Inbound SMTP hardening.** The inbound listener limits concurrent connections and no longer buffers unbounded oversized messages; peers that keep sending far past the size limit are disconnected.

## Upgrading from 0.1.2

- Five additive migrations, `bp0001` to `bp0005`, are applied by the existing migration runner at start. They are tracked by name and add the schema for app passwords, IMAP state and IMAP subscriptions.
- **Back up the persistent volume or database before upgrading.** Downgrading after the migrations have run is not supported; restore the backup to return to 0.1.2.
- IMAP and SMTP submission stay off until you configure them. See [self-hosting](../self-hosting.md#upgrading-from-012-to-020).

## Limitations

- Mozilla Thunderbird 157.0 on Windows is the only tested client. Other clients are not certified.
- IMAP is a limited IMAP4rev1 command set (APPEND only into Drafts; no CONDSTORE or QRESYNC). SMTP submission is implicit TLS on 465 only, with no STARTTLS or port 587, and does not support `SMTPUTF8` addresses, signed or encrypted messages, or Bcc-only messages.
- If delivery status is unknown, the client receives a temporary `451` error and the message may already have been sent. Retrying can produce a duplicate; there is no durable deduplication.
- IMAP and SMTP connection and rate limits are per process and in memory.
- You provision and renew TLS certificates. Managed-service operational hardening is not complete.
- IMAP and SMTP submission are not available on Cloudflare Workers.
